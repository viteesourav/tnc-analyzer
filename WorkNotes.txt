Goal of the Project:

Built an AI-powered Terms & Conditions analyzer using Spring Boot microservices with Kafka-based async processing, Redis caching, OAuth authentication, and rate-limited API Gateway. Extended with browser automation capabilities

Plan for the building the Project:

    1. Project Setup + Architecture
        -> Multi-module repo structure [3 different services under 1 service]
        -> Setup Docker + Docker Compose.
        -> Add Postgress Container
    
    All Services must be running in local

    2. Authentication (OAuth + Jwt)
        -> JWT Generation
        -> Google/Github OAuth
        -> Secure APIs

    Learn about the OAuth flow + Token based auth process
    
    3. Core APIs
        -> fake APIs for testing.
        -> Create actual APIs for POST /analyze + GET /result/{id} + GET /history.

    Learn API designs !

    4. DB Design + Cleanup
        -> Design Schemas to store the responses.
        -> tables: users & analysis.

    5. Async + Infra Enhancements
        -> Add Kafka (docker) + Producers in analsis-service + Consumer (new Service: worker) 

    Learn Event Driven Architecture & Message Flow

    6. AI Integration
        -> Integrate google GemniAI or OpenAI [Anything that is free to use]
        -> Prompt Designing


### Project Architecture

    Gateway → Auth → Analysis Service → Kafka → Worker → AI
                         ↓
                      Postgres
                         ↓
                       Redis

### Service wise seperation:
    1. api-Gateway:
        - Entry point to your system
        - Handles:
            Routing
            Rate limiting (later)
            Request forwarding

        This is where Spring Cloud Gateway belongs
    
    2. auth-service
        - Handles:
            Login (OAuth)
            JWT generation
            User identity

    
    Client → API Gateway → Auth Service → Analysis Service

    -- Gateway routes requests
    -- Auth validates identity
    -- Analysis does business logic

        - PHASE 1: Simple login with JWT
            -- local Login with JWT generation & gateway service validates JWT.

        NOTE:
            1. by-default, when we use spring-boot-security, all end-points are protected.
                - to by-pass this, we added a @Configuration for springboot to disable CSRF and add a pass for sepecific route.
            2. Folder strcuture messup:
                - earlier, we defined controller, config, dto, util under auth -> package: com.tnc.auth
                - the actual service file was under a differnet package all together
                - Concept: The Springboot service discovery scans the folder completely from where it is defined.
                - Solution: We moved to AuthServiceApplication.java  to package: com.tnc [a global package where it can discover all configurations and controllers] 

                !! This one is basic & Most important !!!
            3. The SHA signing with jwt.
                - some issue with the secerte token lenth of character for the HSA256 encription algo.
                - So we increased the size.
                - also as suggested, instead of using string secret key, we are now using a modern Secert object.

            -- Nextup we want to protect our Routes from anyone to access it. 
                - JWT validation can happen at 2 places:
                    1. Gateway   - Validate once at entry.
                    2. Every Service - Each service validates independently.
                - Ideally, Gateway must validate first and then AND/OR service validates too.
                - Updated Flow:
                    Client logs in => Auth service returns JWT => Client sends JWT in Authorization header => Gateway validates JWT => Gateway forwards the request.

                This is "StateLess Authentication"  -> the server doesnot store any session -> JWT itself carries identity.

                - Enabling JWT protected Routes:
                    -> So far, we are able to generate a token (JWT) from auth-service [using dummy creds for admin/password]. -> Since no db or user persisitence added yet !
                    -> we able to verify the APis are protected ?
                        -> In Gateway service -> we added a JWTutil that verify if the token is correct or not ?
                        -> We also added an JwtAuthenticationFiler -> Kind of a post-processor from the Spring cLoud, which provides method that interect the incoming request and we can add any postprocessing in that. => here we are extracting the "Bearer <token>" from header, validating it, making a decision if to allow the user or not !
                    
                This basically addes Token Procted Routes to Gateway Service while re-directing to other services.
