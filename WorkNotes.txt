Goal of the Project:

Built an AI-powered Terms & Conditions analyzer using Spring Boot microservices with Kafka-based async processing, Redis caching, OAuth authentication, and rate-limited API Gateway. Extended with browser automation capabilities

Plan for the building the Project:

    1. Project Setup + Architecture
        -> Multi-module repo structure [3 different services under 1 service]
        -> Setup Docker + Docker Compose.
        -> Add Postgress Container
    
    All Services must be running in local

    2. Authentication (OAuth + Jwt)
        -> JWT Generation
        -> Google/Github OAuth
        -> Secure APIs

    Learn about the OAuth flow + Token based auth process
    
    3. Core APIs
        -> fake APIs for testing.
        -> Create actual APIs for POST /analyze + GET /result/{id} + GET /history.

    Learn API designs !

    4. DB Design + Cleanup
        -> Design Schemas to store the responses.
        -> tables: users & analysis.

    5. Async + Infra Enhancements
        -> Add Kafka (docker) + Producers in analsis-service + Consumer (new Service: worker) 

    Learn Event Driven Architecture & Message Flow

    6. AI Integration
        -> Integrate google GemniAI or OpenAI [Anything that is free to use]
        -> Prompt Designing

### Service wise seperation:
    1. api-Gateway:
        - Entry point to your system
        - Handles:
            Routing
            Rate limiting (later)
            Request forwarding

        This is where Spring Cloud Gateway belongs
    
    2. auth-service
        - Handles:
            Login (OAuth)
            JWT generation
            User identity

    
    Client → API Gateway → Auth Service → Analysis Service

    -- Gateway routes requests
    -- Auth validates identity
    -- Analysis does business logic


### Steps to Start & Run the Application:

    1. First if it's a fresh run: 
        -- Install wsl [wsl --install in cmd] & install Reancher Desktop.
        -- Then in the project dir: We have docker-compose.yml
        -- open cmd: 
            docker compose up -d 
        -- The above spins up the Postgress 16 and other Infra.
    
    2. Go to application.yml of analysis-service: 
        - update the GEMINI_API key to your Gemini_API_KEY.
        - Location: https://aistudio.google.com/api-keys
    
    3. Open 3 seperate cmd: 
        - ./gradlew :analysis-service:bootRun
        - ./gradlew :auth-service:bootRun
        - ./gradlew :api-gateway:bootRun

    4. Once the services are up & running: 
        - Open the Postman Collection in Postman.
        - Steps:
            1. APIs are protected: Hit the login API first.  --> You get JWT token.
                - If new user -> Register the user First.
            2. then With the token:
                -> hit /analysis with the JSON payload.

            -> WebClient: 
                WebClient is a modern, non-blocking, reactive HTTP client included inside the WebFlux dependency. It is used to make HTTP calls to external APIs or other microservices. [** IMP **]
            -> Difference between WEb-Client Vs REST Template:
                1. non-blocking
                    -- If your service calls an external API that takes 5 seconds to respond, RestTemplate will freeze that execution thread for the entire 5 seconds. 
                    -- WebClient fires the request, immediately frees up the thread to handle other tasks, and executes a callback whenever the external API finally responds.
                2. Support both async and sync workflows
                    -- Even if you aren't building a fully reactive application, you can still use WebClient in a standard blocking application by appending .block() at the end of the call chain.
                3. Standard Practise.
                    -- Spring has officially deprecated RestTemplate into maintenance mode, making WebClient the designated tool for HTTP communication in modern Spring apps.
